{{< lead >}}
The dashboard exists. What it is supposed to graph does not.
{{< /lead >}}

{{< alert icon="triangle-exclamation" >}}
**This component is half-built.** Grafana runs at `grafana.apexarcology.com`. There is no
Prometheus in this cluster — a repo-wide search finds it only as scrape annotations on one
deployment, never as a deployed workload. Grafana therefore has nothing to query unless a
datasource is added by hand in the UI. Calling this "monitoring" is generous.
{{< /alert >}}

## What it is

A Grafana instance, installed from the upstream Helm chart, exposed through
[Traefik](../traefik/).

Grafana is a *query and display* layer. It does not collect anything. It needs a datasource
— Prometheus for metrics, Loki for logs — and neither is deployed here.

## Why this one

The intent was the standard stack: Prometheus scraping, Grafana displaying, alerts on top.
Grafana went in first because it is the part you look at, which was the wrong order — the
visible half got done and the useful half didn't.

The honest state of observability in this cluster is `kubectl logs` and
[HolmesGPT](../holmesgpt/), which reads live cluster state rather than stored metrics.
That works precisely because there are no stored metrics to read.

## Where it lives

| | |
|---|---|
| Namespace | `monitoring` |
| Manifests | `k8s/bootstrap/monitoring/` |
| ArgoCD app | `k8s/apps/templates/monitoring.yaml` |
| Chart | `grafana` from `https://grafana.github.io/helm-charts` |
| Chart version | `"*"` — **unpinned** |
| Service port | `80` |
| URL | `https://grafana.apexarcology.com` |

`targetRevision: "*"` takes whatever the latest chart is at sync time. See
[External Secrets](../external-secrets/) for why this is a problem across three components
here.

## Usage

```bash
kubectl -n monitoring get pods
kubectl -n monitoring logs deploy/monitoring-grafana --tail=30
```

The admin password is generated by the chart into a Secret:

```bash
kubectl -n monitoring get secret monitoring-grafana \
  -o jsonpath='{.data.admin-password}' | base64 -d
```

### Making it actually useful

The missing work, in order:

1. Deploy Prometheus (kube-prometheus-stack is the obvious choice, and it bundles Grafana —
   which would replace this install rather than complement it).
2. Configure the datasource **as chart values in git**, not through the UI. A datasource
   added by hand disappears the next time the pod is rescheduled, because there is no
   persistence configured either.
3. Pin the chart version.

## Troubleshooting

**Grafana loads but every panel says "No data".**

There is no datasource. This is the current state, not a fault.

**Dashboards or datasources vanished after a restart.**

No persistence is configured, so Grafana's SQLite database lives in the pod's ephemeral
filesystem. Anything created through the UI is lost on reschedule. Configuration belongs
in chart values.

**Cannot log in.**

Pull the generated password from the Secret above. If the Secret was regenerated by a chart
upgrade — likely, given the unpinned version — the old password stops working.
